MCP Tools Reference

Academic Hunter exposes 44 tools via the Model Context Protocol (MCP), along with Resources and Prompts. All 44 are documented below, grouped by category, with parameters, types and examples. Any MCP-compatible client — Claude Desktop, Cursor, or custom agents — can drive the research pipeline autonomously.

Setup

Add the following server configuration to your MCP client. The auto-installer (python install.py) can do this for you.

Stdio mode (default)

{
  "mcpServers": {
    "academic-hunter": {
      "command": "academic-mcp"
    }
  }
}

Or, if running from source without installing the CLI entry point:

{
  "mcpServers": {
    "academic-hunter": {
      "command": "/path/to/venv/bin/python",
      "args": ["-m", "academic_hunter.interfaces.mcp.server"],
      "env": {
        "PYTHONPATH": "/path/to/academic-hunter/src"
      }
    }
  }
}

After connecting, the tools appear automatically in your MCP client. Use the quick_topic_discovery tool first to identify jargon, then configure your search via update_config, and run it with run_search.

SSE mode (HTTP + Server-Sent Events)

Run the server with SSE transport for environments that need an HTTP endpoint (e.g., remote agents, containerised deployments): 

# CLI flags
academic-mcp -t sse --host 0.0.0.0 --port 8080

# Or via environment variables
export ACADEMIC_MCP_TRANSPORT=sse
export ACADEMIC_MCP_HOST=0.0.0.0
export ACADEMIC_MCP_PORT=8080
academic-mcp

In SSE mode the server exposes a health check endpoint at GET /health and streams tool responses over SSE. Connect your MCP client to http://<host>:<port>/sse.

Health Check

Verify the server is running with a simple HTTP request: 

curl http://127.0.0.1:8080/health

# Response:
{
  "status": "ok",
  "server": "academic-hunter",
  "config_loaded": true,
  "vector_store": {
    "available": true,
    "paper_count": 47
  }
}

The health endpoint returns a JSON object with overall status (ok, degraded, or error) and per-component diagnostics for the configuration and vector store.

Environment Variables

Variable Default Description
ACADEMIC_MCP_TRANSPORT stdio Transport protocol: stdio or sse
ACADEMIC_MCP_HOST 127.0.0.1 Bind address for SSE mode
ACADEMIC_MCP_PORT 8080 Port for SSE mode

update_config

Configuration

Updates the project's config.json with new research parameters. A backup is automatically saved to the SQLite history before applying changes. You can provide a full or partial SearchConfigUpdate object.

update_config(config_update: SearchConfigUpdate) → str
Parameter Type Required Default Description
topic Optional[str] No — Short name for this config (e.g., "CBDC Latency 2025")
settings Optional[Dict] No — System settings (min_relevance_score, start_year, limit_per_query)
anchors Optional[Dict] No — Mandatory keyword groups. At least one term from each group must match.
technical_strings Optional[Dict] No — Taxonomy categories for your technical terms
technical_weights Optional[Dict] No — Weighted terms (5.0=core niche, 3.0=protocols, 1.5=generic)
context_rules Optional[Dict[str, List[str]]] No — Disambiguation rules — maps ambiguous terms to required context words
keyword_only_terms Optional[List[str]] No — Generic keywords for fallback search
keyword_only_category Optional[str] No — Aggregating category for keyword-only terms

Returns: Confirmation message with the applied configuration summary.

# Example — ask your MCP client:
"Configure Academic Hunter for CBDC latency research starting from 2022."

# The agent calls update_config with appropriate anchors and weights.
# Result:
"Configuration updated successfully. Backup saved to history (ID: 7)."

run_search

Search

Executes the full academic search pipeline. Spawns concurrent workers for each API connector (Semantic Scholar, OpenAlex, Crossref, ArXiv, CORE, DBLP, DOAJ), deduplicates results, scores them, generates reports, and indexes papers into the vector store.

run_search(limit_per_source: int | None = None) → str
Parameter Type Required Default Description
limit_per_source int | None No None Override the global limit_per_query from config.json for this run

Returns: Path to the generated Markdown report and summary of results.

# Example — ask your MCP client:
"Run a search for the current configuration."

# Or with a custom limit:
"Run a quick search with just 10 results per source."

# Result:
"Search complete. 47 papers found, 23 passed relevance scoring.
Report saved to results/FLUXO_PRISMA_20260715_103022.md"

summarize_paper

Discovery

Fetches the paper's abstract and selects the sentences that carry it: first the one closest to the centroid, then Maximal Marginal Relevance for the rest, so each new sentence adds something the chosen ones do not already say. Extractive only — every sentence returned is the author's, which is what keeps the summary free of invented claims.

summarize_paper(doi: str, num_sentences: int = 3) → str
Parameter Type Required Default Description
doi str Yes — DOI of the paper to summarize
num_sentences int No 3 Number of sentences in the summary (capped at 8)

Returns: Markdown with the selected sentences, in their original order. Needs sentence-transformers; an abstract with fewer sentences than requested is returned whole.

# Example — ask your MCP client:
"Summarize doi:10.1234/atomic in three sentences."

# Result:
"# Extractive Summary

**DOI:** 10.1234/atomic
**Method:** Centroid + MMR (MiniLM)
**Sentences:** 3
---

**1.** We measure settlement latency across four DLT networks.

**2.** Median latency stays below one second for two-party transfers.
..."

rerank_search

RAG

Retrieves with the bi-encoder (MiniLM) and then re-orders the candidates with a cross-encoder when sentence-transformers is installed — the second stage that pays where the bi-encoder does not. It is slower, so it only ever sees the top candidates. Without it the tool says so and returns the bi-encoder order rather than failing.

rerank_search(query: str, top_k: int = 20, rerank_k: int = 5) → str
Parameter Type Required Default Description
query str Yes — Search query
top_k int No 20 Initial candidates fetched from the bi-encoder
rerank_k int No 5 Final results returned after re-ranking

Returns: Markdown list with relevance, year, DOI and a 200-character preview.

# Example — ask your MCP client:
"Search cross-chain settlement, but re-rank the top results."

# Result:

verify_citations

Writing

Runs the existence layer over every [@key] citation in the text. Three probes are attempted, each only when the information to answer it exists: the bibliography, the DOI resolving at Crossref, and the local corpus. A citation is NOT_FOUND as soon as an available probe fails, and UNKNOWN when nothing could be checked — could-not-verify is never reported as fabricated.

fulltext_status

Full Text

Reports coverage for the last run: how many full texts were obtained, how many had no open-access copy, how many failed to download and why, and how many were already indexed by an earlier run. It also reports whether the optional pypdf extra is installed — without it only Europe PMC can deliver text, and "0 obtained" would be misread as "there is no open access".

fulltext_status() → str

Returns: Per-status counts from the last run's dataset, the persistent chunk count of the paper_chunks collection, and the configuration state.

index_fulltext

Full Text

Resolves each paper's open-access copy, downloads it, extracts the text and indexes 180-word passages into paper_chunks. Sources are chained: Unpaywall first, Europe PMC after — the second recovers papers Unpaywall knows to be open while naming no PDF. Papers already indexed are skipped unless force, so a repeated call is cheap. Does not require settings.fulltext.enabled; the pipeline step does.

index_fulltext(force: bool = False, limit: int = 0) → str
Parameter Type Required Default Description
force bool No False Re-fetch and re-index papers that already have chunks
limit int No 0 Cap how many papers to attempt (0 = the configured maximum)

Returns: Counts per status — obtained, already indexed, no open access, download failed, no text layer, no sections, no DOI, not attempted.

chunk_search

Full Text

Answers what an abstract cannot: which dataset was used, how many annotators coded the corpus, what the method actually did. Returns the passages grouped under the paper they came from, with the section and the character offsets within the extracted text. There is no page number — a PDF has pages and the Europe PMC JATS source has none, so a page field would exist for half the papers.

Parameter Type Required Default Description

per_paper int No 3 How many passages to show per paper
collection_name str No "paper_chunks" Chunks collection to search

Returns: Passages grouped by paper, each with its section, chunk index, character offsets and relevance.
