# Auditoria do Academic Hunter — 16/09/2026

## Parecer

O projeto está **materialmente melhor** do que na auditoria de 14/09: os 30 achados
daquela foram tratados, o CI saiu do vermelho depois de sete semanas, e a suíte cresceu
para 1052 testes.

Esta auditoria encontrou **dois defeitos que as duas passadas anteriores não viram** —
um no funil de dados, um na ferramenta que existe para conferir números — e uma cauda de
contratos frouxos. Nenhum deles é de estilo; todos têm consequência.

Os dois que importam:

1. **O merge de metadados entre cópias da mesma obra quase nunca acontece**, e a cópia
   perdedora é descartada inteira — com o DOI dela. A identidade do paper **muda entre
   execuções do mesmo corpus**.
2. **O verificador de números endossa p-valores fabricados**: qualquer `0.0` nos arquivos
   de resultado "confirma" um p-valor pequeno. A ferramenta cujo propósito é pegar um
   número que nenhum experimento produziu é a que o produz.

## Escopo e método

- **Base:** `7990722`, o repositório inteiro — 13,6 mil linhas em `src/` (`core` 5.615,
  `interfaces` 4.586, `plugins` 2.945, `app` 433) e 17,6 mil em testes.
- **Método:** leitura de código **mais execução**. O pipeline foi rodado com conectores
  falsos e os artefatos lidos; campos hostis foram injetados; runs repetidos foram
  comparados entre si; o servidor MCP foi exercitado.
- **Regra:** nenhum achado entra sem reprodução, e a coluna **Verif.** diz quem
  reproduziu. `eu` = reconferido nesta sessão, independente do auditor de área.
  `área` = reproduzido pelo auditor da área, com o script em `/tmp/audit/`.
- **Limites:** nada foi executado contra as APIs reais (sem rede). O full-text não foi
  exercitado ponta a ponta. A medição de mutação cobriu `core/nlp/fusion.py` (93%), não
  o domínio.

## P1

### A01 — O merge de metadados não acontece, e a cópia perdedora leva o DOI embora

**Verif.: eu** · `core/screening/processor.py:50-69`, `core/screening/resolvers.py:78-90`,
`core/models/paper.py:36-58`

Quando duas fontes devolvem a mesma obra, o duplicado é decidido sob o lock e a validação
roda **fora** dele, com a escrita em `consolidated_results` só no fim. O merge de
metadados é condicionado a `existing = consolidated_results.get(dedup_id)` não ser `None`.
Uma cópia que chega durante a validação encontra `None`, e o código conclui — por
comentário explícito, na linha 58 — que ela "has nothing to do", descartando-a.

Ela tem: o DOI, o abstract mais longo, as citações, a fonte a somar. As estratégias por
campo de `FIELD_SCHEMA` (`first_non_empty` para DOI/URL, `longest_string` para abstract,
`max` para citações, `set_join` para `Source`) existem para combiná-las e não são aplicadas.

```
$ PYTHONDONTWRITEBYTECODE=1 ./venv/bin/python /tmp/real_trace.py
  Source='ArXiv'  DOI=''  citations=1
  abstract='Blockchain latency.'
  duplicatas removidas: 2
  Paper.merge chamado: 0 vez(es) []
```

Três fontes, a mesma obra; só a terceira traz o DOI, só a segunda o abstract longo. O
registro final fica com os campos da primeira e mais nada. A ordem decide:

```
arXiv(primeiro, sem DOI) + Crossref          DOI=''           Source='ArXiv'
arXiv COM o DOI primeiro (ordem trocada)     DOI='10.1/x'     Source='Crossref'
```

E **varia entre execuções do mesmo corpus** — doze runs, campos por obra:

```
'Payment rails compared'  DOI=''        Source='ArXiv'            <- às vezes
'Payment rails compared'  DOI='10.1/c'  Source='ArXiv, Crossref'  <- outras vezes
'Ledgers at scale'        DOI=''        Source='ArXiv'            <- sempre
```

**Consequências.** (a) **A identidade muda entre execuções**: `doc_id_for` devolve
`doi:10.1/c` ou `title:paymentrailscompared`, e é esse id que o qrels, os julgamentos e os
chunks de full-text usam. (b) O full-text marca `no_doi` e nunca tenta. (c) O `.bib` sai
sem `doi`. (d) O PRISMA credita **uma** fonte a um paper que três devolveram — numa
ferramenta cuja seção vizinha se chama "Reproducibility Metadata".

**Por que sobreviveu a duas auditorias.** O defeito é mascarado sempre que a cópia que
chega primeiro é a mais rica, e o sintoma (um DOI a menos) é indistinguível de um dado que
nunca teve DOI. Dos 108 documentos julgados, os 25 sem DOI vêm **todos de fonte única**;
os com DOI incluem fontes fundidas. Consistente com o mecanismo — mas **não prova** que
aqueles 25 perderam um DOI: isso exigiria remedir a coleta. **Hipótese.**

### A02 — O verificador de números confirma p-valores que não existem

**Verif.: eu** · `core/writing/numbers.py:211-220, 254-275`

`_decimals` faz `len(repr(float(v)).split(".")[1].rstrip("0"))`. Para `1.57e-73` o `repr`
é `'1.57e-73'`, então a "parte decimal" é `'57e-73'` → **6 casas**. Daí
`target = round(1.57e-73, 6) == 0.0`, e a comparação `round(scaled, decimals) == target`
aceita qualquer valor do índice que arredonde para 0.0 — inclusive o `0.0` que todo run
tem (`excluded_year: 0`, `duplicates_removed: 0`).

```
$ ./venv/bin/python (script próprio, base 7990722)
  'p = 1.57 × 10⁻⁷³'  -> MATCHED   (result files contain 0.0)
  'p = 8.40 × 10⁻⁷'   -> MATCHED   (result files contain 0.0)
  'p = 1.20 × 10⁻¹⁰'  -> MATCHED   (result files contain 0.0)
  'p = 3.20 × 10⁻⁵'   -> CLOSE
  'p = 1.20 × 10⁻²'   -> UNSOURCED
```

Atinge p ≲ 1e-6. E `format_statistical_claim` (`core/writing/style.py:206-212`) produz
exatamente esse rendering em notação científica, então os dois módulos combinam para
fabricar a confirmação.

**Nota.** A auditoria de 14/09 apontou um defeito vizinho — "`p = 1.57e-73` vira `1.57`" —
e a correção (`580ca32`) consertou a **extração** do expoente. O caminho de **comparação**
ficou. Um conserto que endereça o sintoma nomeado sem medir o mecanismo.

### A03 — O reload de configuração atualiza os dicionários, não os padrões compilados

**Verif.: área** · `core/infra/config.py:118-127` × `core/nlp/scorer.py:22-25`

`load()` passou a atualizar as seções in-place. Mas `AcademicScorer.__init__` deriva
`self.compiled_patterns` **uma vez**, e é isso que `calculate_score` itera. Só o setter da
facade reconstrói os padrões; `load_config()` não passa por ele.

```
before reload: weights={'ledger': 1.0}  patterns=['ledger']
after  reload: weights={..., 'throughput': 7.0}  patterns=['ledger']
  score('throughput') = 0.0  <- stale
```

`tech_weights` é a **mesma** grandeza com dois caminhos de escrita que discordam.
`tests/core/test_config_reload.py:47-57` asserta sobre o dict — que é o mesmo objeto já
atualizado — e passa pelo motivo errado.

### A04 — Números hostis: o funil não fecha, e o PRISMA se contradiz

**Verif.: área** · `core/pipeline/steps.py:184-188` × `core/screening/resolvers.py:164,221`;
`core/screening/processor.py:24-35`

Dois contadores para a mesma exclusão: `excluded_technical_score` é **recalculado** pelo
rank step (contra `min_relevance_score`), enquanto `exclusions_by_source[src]["score"]` só
é incrementado no ingest (contra `min_inclusion_score()`). Gates diferentes, escalas
diferentes, e o mesmo relatório mostra os dois:

```
- **Excluded (Low Relevance Score):** 1
| **Mock** | 1 | 1 | 0 | 2 |      <- "Low Tech Score" = 0, "Total Excluded" = 2
```

E `stats["identified"][source] += 1` acontece **antes** de `if not title: return`, sem
contador para esse descarte — então um registro sem título entra no funil e não sai por
lugar nenhum. O Mermaid renderiza a lacuna: `Unique Records: 2 → Passed: 2 → Passed: 2 →
Failed Score: 0 → Passed: 1`.

### A05 — Seis de nove regras de contexto nunca podem disparar

**Verif.: área** · `core/nlp/scorer.py:135-148`

`validate_anchor_context` normaliza o texto para minúsculas e faz
`self.context_rules.get(term)`, mas as chaves entram verbatim do JSON. Com chaves em caixa
mista (`Grover`, `NISQ`, `IBM Quantum`), o `.get()` devolve `None`, o `if required_keywords`
é falso e **a validação contextual é pulada em silêncio** — inclusive a regra
anti-colisão "AI/ML × Drex", que é o motivo do mecanismo existir. Nenhum teste passa
`context_rules` com chave maiúscula.

### A06 — `rank_geometric` inventa uma escada 0-10 a partir de zero evidência

**Verif.: área** · `core/nlp/fusion.py:20-35, 93-96`

Para sinais constantes, `percentile_ranks` desempata **pela ordem de inserção**, e
`sqrt(a*b)*10` transforma isso em scores distintos:

```
n=4, zero evidence, weighted_norm : [0.0, 0.0, 0.0, 0.0]
n=4, zero evidence, rank_geometric: [0.0, 3.333, 6.667, 10.0]
```

O último paper recebe 10.0 e passa o limiar. Qual é "o último" depende da ordem de chegada
das threads. A estratégia irmã tem guarda explícita **e** teste
(`test_a_flat_signal_with_no_evidence_does_not_tie_at_the_top`); `rank_geometric` não tem
nenhum dos dois. É a estratégia legada, mantida para reproduzir runs antigos — e é a que
não reproduz.

### A08 — Override por variável de ambiente é gravado em `config.json`

## B01 — P1 — O recurso de paper por DOI é inalcançável para todo DOI real
**Verif.: eu** · `interfaces/mcp/server.py:111`, `resources.py:104-130`

O template publicado é `academic-hunter://papers/{doi}` — **um** segmento de URI. Todo
DOI contém `/`, então o template nunca casa; forçando o casamento com `%2F`, o handler
não decodifica e devolve o DOI corrompido (`10.1038%2F…`), que um agente pode reusar em
citação. Medido contra um DOI que existe no último run:

```
academic-hunter://papers/10.1038/s41586-024-08449-y    -> ERROR: Unknown resource
academic-hunter://papers/10.1038%2Fs41586-024-08449-y  -> casa, devolve doi com %2F
tool fetch_paper_by_doi (mesmo DOI)                    -> encontra o abstract
```

## B02 — P1 — Três análises apresentam uma vizinhança de similaridade como "o corpus"
**Verif.: eu** · `visualization.py:54,119`, `novelty.py:34`

`_utils.py:148-166` define `corpus_of()` exatamente para impedir isto, e o seu docstring
diz a consequência em voz alta ("the analyses then describe that neighbourhood instead,
without saying so"). `clustering.py:60`, `dedup.py:37` e `trending.py:47` a usam. Estes
três não — e usam **três frases fixas diferentes**, cada uma decidindo qual recorte é
apresentado como a coleção:

| Local | Frase fixa | Consequência |
|---|---|---|
| `visualization.py:54` | `"research paper topic analysis"` | a projeção UMAP "do espaço de embeddings" |
| `visualization.py:119` | `"research topic analysis"` | a "evolução dos tópicos ao longo do tempo" |
| `novelty.py:34` | `"research novelty outlier detection"` | os "artigos atípicos do corpus" |

Medido contra o corpus real: `corpus_of(store)` → 10.790 papers; a vizinhança da frase →
500, encabeçada por papers *sobre análise de gênero de abstracts*. As descrições
publicadas prometem a coleção. **A correção de 14/09 que passou clustering, dedup e
trending para `corpus_of` deixou estes três de fora.**

## B04 — P2 — Trabalho bloqueante no event loop, e `semantic_dedup` derruba o servidor
**Verif.: área** · oito sítios, medidos com heartbeat (loop livre = 0,20 s)

| Local | Chamada no loop | Heartbeat |
|---|---|---|
| `dedup.py:57-75` | matriz 10.790² + laço O(n²) em Python puro | **~16 s**, 466 MB |
| `writing.py:346-361,376` | `requests.get(timeout=10)` | 1,66 s |
| `novelty.py:34` | `store.query` | 1,35 s |
| `rag.py:152-153` | `collection_stats` + `list_collections` | 1,00 s |

O projeto tem regra explícita (`_utils.py:25-35 run_blocking`) e a viola aqui. O contraste

## B05 — P2 — Cada chamada de tool constrói o seu próprio hunter
**Verif.: área** · `_utils.py:61-63`, `app/main.py:41-42`

O `RLock` e o `Semaphore(2)` que limitam a concorrência e o pacing por domínio — a
proteção contra ban das APIs — são **por instância**, e cada chamada de tool cria a sua.
Duas chamadas concorrentes adquirem 4 permissões onde o teto pretendido é 2, e o
espaçamento por domínio se perde. `_get_vector_store()` também cria um cliente Chroma
novo por chamada, nunca fechado.

- **`interfaces` importa `plugins`** (`_utils.py:10`, `export.py:17-19`, `obsidian.py:5`,
  `unpaywall.py:22`), embora `app/__init__.py:13-16` afirme que só `app` o faz — e

## C06 — P2 — Achados médios

- **BibTeX não escapa `%`** (`bibtex.py:12-16`): no passo LaTeX o `%` comenta até o fim da
  linha, engolindo o `},` e desbalanceando as chaves. O teste de escape só cobre `}` e `\`.
- **O esquema do CSV depende de o run ter dados** (`csv.py:41` vs `:51-59`): no run vazio
  `Database_Count` é a **primeira** coluna; com dados, a **nona**. E o CSV real tem 23
  colunas, incluindo `_hybrid_score`, `_rank_kw`, `_full_text_status` — campos internos cuja
  presença varia conforme a etapa rodou. Nenhum dos 123 CSVs de run é vazio: o caminho do
  run vazio nunca foi exercitado de verdade.
- **`make install` não funciona no alvo declarado** (`Makefile:14-15`): usa o `pip` nu
  (`/usr/bin/pip`, PEP 668 `externally-managed-environment` no Ubuntu 24.04) enquanto o resto
  do Makefile usa `$(VENV)/bin/…`, e omite o extra `fulltext` que o `install.py` chama de
  "not optional in practice".
- **Campos nulos viram o texto `"None"`** (`core_ac.py:63`, `openalex.py:101,104`): o default
  de `.get()` só vale quando a **chave** falta. `year = {None}` no BibTeX, `PY  - None` no
  RIS. 15,7% dos registros reais do CORE têm `yearPublished` nulo. Absorvido dentro do
  pipeline pela normalização do `Paper`; é o contrato do plugin e de quem o chama com dicts
  crus.
- **`neutralise_formula` não cobre TAB nem CR** (`csv.py:12`): `"\t=1+1"` passa.
- **`index_papers` descarta o lote inteiro** por um id repetido (`chroma.py:197,223`): dois
  papers sem DOI com o mesmo título viram o mesmo id e o `upsert` levanta, perdendo também
  os que estavam certos.

## C07 — O que NÃO se achou defeito

- **Similaridade no ChromaDB está correta.** As coleções antigas foram criadas antes de o
  código declarar `hnsw:space` e o Chroma reporta `l2`; `1 - d/2` é a conversão certa
  porque os vetores são unitários — medido: norma `min=max=média=1.000000` em 200 embeddings
  reais, e num par real `l2²=1.2311 → 1-d/2=0.3844 == cos=0.3844`.
- **`normalize_doi` acerta** os 15.909 DOIs distintos das respostas reais do OpenAlex.
- **Credenciais limpas**: nenhuma chave vai para log, artefato ou outro serviço; o
  `run_stats.json` carrega só `start_year`, `min_relevance_score`, `limit_per_query`.
- **`safe_xml.parse_xml` recusa DTD/ENTITY**; o download do Unpaywall valida `%PDF-` e
  aplica o teto duas vezes.
- **`requires-python = ">=3.10"` parece verdadeiro** — busca por sintaxe 3.11+/3.12 em
  `src/` não achou nada e o ruff aponta `py310` (estático; a matriz não roda nesta máquina).
