Por que hexagonal + plugins?

Cada conector é um plugin independente — adicionar uma nova fonte de dados não exige modificar o núcleo. O scorer, o vector store e os exporters seguem o mesmo padrão. Atualmente são 15 conectores, mas a arquitetura permite escalar para dezenas sem impacto no resto do sistema.

Parte 2 · Integração com IA

6 MCP: A Ponte entre SLR e Agentes de IA

MCP (Model Context Protocol) é um padrão aberto, criado pela Anthropic e adotado pela Linux Foundation, OpenAI e Google. Permite que QUALQUER agente de IA se conecte a ferramentas externas.

🔧 Na prática: Imagine que você pede pro Claude fazer uma revisão sobre CBDC. O Claude:

Pesquisador: "Faça uma SLR sobre impacto de CBDCs na estabilidade financeira" # Claude (via MCP) planeja e executa: → quick_topic_discovery("CBDC financial stability") # descobre jargões → semantic_search("CBDC bank disintermediation") # busca por conceito → cluster_papers(top_k=500) # agrupa por tema → find_novel_papers() # detecta outliers → visualize_landscape(top_k=500) # mapa 2D → export_to_obsidian("CBDC Review") # salva no seu Second Brain Pesquisador: valida o resultado em 15 minutos, não em 6 meses

Parte 2 · O Que Não É

7 O Que Academic Hunter É — e Não É

Importante entender o papel de cada peça:

❌ Não é um ChatGPT

Não gera texto, não inventa respostas, não alucina. Ele recupera e analisa o que já foi publicado.

❌ Não é um agente autônomo

Ele é uma caixa de ferramentas que um agente IA usa. Quem decide o que fazer é o agente (ou você).

✅ É um motor de busca semântica

Entende o significado dos textos, não só as palavras. "CBDC" e "moeda digital do banco central" são a mesma coisa para ele.

✅ É a "parte inteligente" de um sistema maior

Na literatura, isso se chama Agentic RAG: um agente IA orquestra ferramentas especializadas. O Academic Hunter é a ferramenta especializada em SLR.

Parte 4 · O Coração Técnico

13 O Problema: Como dar "peso" às palavras num embedding?

"O bi-encoder usa repetição de termos"
↓ O método padrão (mean pooling) dá o MESMO peso para TODAS as palavras

📊 Analogia: Pesquisa de Opinião

Mean pooling é como uma pesquisa onde todo mundo tem 1 voto — inclusive quem não entende do assunto.

Pesquisador sobre "CBDC" quer que "banco central" e "moeda digital" tenham mais peso que "o", "um", "para".

🎯 Dois Problemas Práticos

1. Scores comprimidos: artigos parecidos ficam com scores muito próximos.

2. Sem controle: o pesquisador não consegue dizer "isso é mais importante".

Parte 4 · A Solução

14 Weight-Bleeding: Ponderação Semântica Configurável

💡 Ideia central: Se repetir um termo no texto fizesse ele contribuir mais, por que não fazer isso diretamente no espaço de embeddings? É matematicamente equivalente — mas sem aumentar o texto, sem custo extra, sem precisar de GPU.

📋 Exemplo de Configuração

{"CBDC": 5.0, # termo central, peso alto "moeda digital": 5.0, "banco central": 5.0, "liquidez": 2.0, # relevante mas secundário "blockchain": 2.0}

🎯 O Que Acontece

O sistema calcula um centroide ponderado — uma "posição alvo" no espaço de embeddings.

Cada artigo é comparado com esse centroide: quanto mais próximo, mais relevante.

Artigos sobre blockchain SEM CBDC não são afetados.

⏱ Tudo em CPU, milissegundos por artigo, zero dados de treinamento.

Parte 5 · Transparência

19 Limitações e Quando NÃO Usar

Nenhuma ferramenta é perfeita para tudo. Academic Hunter é ótimo para:

✅ Ideal para

SLRs exploratórias, revisões rápidas, análise de tendências, mapeamento de campo, snowballing semântico, pré-seleção para revisão manual.

⚠️ Não substitui

Revisão manual completa (PRISMA full), meta-análise estatística, avaliação de risco de viés (RoB), extração manual de dados — o pesquisador sempre valida.

❌ Não faz

Não gera texto, não "escreve" a revisão, não toma decisões, não avalia qualidade metodológica dos artigos.

📌 Em desenvolvimento

Cross-encoder é opcional (pesado), APIs do Semantic Scholar/Lens.org podem pedir chave gratuita para alto volume.
